1. Architecture overview
------------------------

Part A (Stages 1–3):

  User action (click, form submit, route change)
        |
        v
  React component  --->  CartContext actions / router.navigate()
        |
        v
  UI updates, cart saved to localStorage

Part B (Stages 4–5) adds one layer, without changing Part A's structure:

  CartContext actions / router / pages  --->  src/analytics/track.ts
                                                      |
                                                      v
                                   window.dataLayer.push({ event, ecommerce })
                                                      |
                                                      v
                                  Google Tag Manager -> GA4 tags, Meta tags

Key decisions:

a) Routing: a tiny custom router (~40 lines, History API: pushState +
   popstate) instead of react-router. Keeps dependencies minimal and gives
   ONE place where every route change happens (useful later for page_view).
   Routes:
     /                 Home (hero, catalog, benefits)
     /product/:id      Product details
     /cart             Shopping cart
     /checkout         Checkout form
     /confirmation     Order confirmation
   The router must respect Vite's base path (import.meta.env.BASE_URL),
   because GitHub Pages serves the site from /<repo-name>/.

b) State: React Context + useReducer for the cart (CartProvider + useCart
   hook), persisted to localStorage. No Redux. Cart changes go through
   named action functions (addToCart, removeFromCart, ...), never raw
   dispatch from components — this is good structure on its own and is
   also where Stage 4 will hook in analytics.

c) React StrictMode stays ON.

d) Privacy by design from day one: the checkout form data is validated
   in the browser only, never sent anywhere and never stored. The stored
   Order contains only products, totals, transaction id and the delivery
   METHOD id.

e) Hosting: GitHub Pages, built and deployed by a GitHub Actions workflow
   (free, HTTPS). Details in Stage 3.

Decisions deferred to Part B (Stage 4): page_view strategy, GTM ID
configuration via VITE_GTM_ID, dataLayer utility, data-gtm attributes.
