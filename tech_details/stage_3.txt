======================================================

Goal
----
Verify the analytics-free store works end to end, put the code on GitHub
and publish it on GitHub Pages (free HTTPS). This is the MILESTONE that
closes Part A: a live, fully working store with zero tracking.
Analytics work (Stage 4) starts only after this stage is done.

-----------------------------

   .idea are ignored. Decide about tech_details/ (recommended: ignore the

     - GitHub CLI: `brew install gh`, `gh auth login`, then
       `gh repo create skin-care-demo --public --source=. --push`

   analytics-free version is always easy to return to and compare against.


3.3 Deployment — GitHub Pages via GitHub Actions
------------------------------------------------
Why public HTTPS matters (also for Part B): Meta Pixel Helper / Events
Manager, GA4 and Tag Assistant work best on a real public URL; teammates
can test; same setup as real sites.

a) Base path. The site is served from https://<user>.github.io/<repo>/.
   vite.config.ts: base = process.env.BASE_PATH ?? "/"  (so local dev stays
   at "/"; the workflow sets BASE_PATH=/<repo>/). The router already uses
   import.meta.env.BASE_URL (Stage 2 §2.2).

b) SPA fallback. GitHub Pages has no rewrite rules, so a refresh on
   /<repo>/product/cream_001 would 404. Use the standard trick:
   - public/404.html: a tiny script that saves the requested path
     (location.pathname + search + hash) to sessionStorage and redirects
     to the base URL;
   - the router (Stage 2 §2.2) restores it on startup with replaceState.
   Simpler alternative: copy dist/index.html to dist/404.html in the
   workflow (works, but the response status is 404 — acceptable for a
   demo; pick one approach and document it).

c) .github/workflows/deploy.yml (official Pages actions):
     on: push to main + workflow_dispatch
     permissions: contents read, pages write, id-token write
     job build: actions/checkout, actions/setup-node (LTS, cache npm),
                npm ci, npm run lint, npm run build with
                BASE_PATH=/${{ github.event.repository.name }}/,
                actions/upload-pages-artifact (path: dist)
     job deploy: actions/deploy-pages, environment github-pages
   Stage 4 will add one env line here for VITE_GTM_ID — nothing else.

d) Repository -> Settings -> Pages -> Source: "GitHub Actions".

e) Push to main -> Actions tab shows the run -> site is live at
   https://<user>.github.io/<repo>/. Put the URL in the repo "About" box.

Alternatives (short note in README): Netlify / Vercel (connect the same
GitHub repo; base path "/", SPA rewrite instead of 404.html).
