4.1 Concepts section (simple English)
-------------------------------------
- What GTM, a container, tags, triggers and variables are.
- dataLayer event vs analytics event: the website announces "something
  happened" (dataLayer event); GTM decides which tools hear about it and
  under which name (GA4 event, Meta event). One dataLayer event can feed
  several analytics events.
- Browser page load vs SPA route change; GA4 automatic page_view vs
  GTM-managed page_view; the approach this project uses and why
  (see Stage 1 §d), and how duplicates appear if both are on.
- Consent note: real sites may need a consent banner / Consent Mode
  depending on law (GDPR etc.), location and ad setup; this demo does not
  implement one and is NOT legally compliant for production.

4.3 docs/gtm-setup.md
---------------------
1. Create a GTM account + Web container; find the GTM-XXXXXXX ID.
2. Put the ID into .env (local) / Netlify env vars (live); restart/rebuild.
3. Verify installation (view source / Network gtm.js / Tag Assistant).
4. Create Data Layer Variables:
     DLV - ecommerce.value, DLV - ecommerce.currency, DLV - ecommerce.items,
     DLV - ecommerce.transaction_id, DLV - page_path, DLV - page_title …
   (Data Layer Version 2.)
5. Create Custom Event triggers, one per event (CE - add_to_cart …), or one
   regex trigger for all GA4 ecommerce events
   ^(view_item_list|select_item|view_item|add_to_cart|...|purchase)$.
6. Folder/naming convention: "GA4 - Event - add_to_cart",
   "Meta - AddToCart", "CE - add_to_cart".
7. Preview mode, Submit + Publish, versions.


4.4 docs/ga4-guide.md
---------------------
1. Create GA4 property + Web data stream; find G-XXXXXXXXXX.
2. Enhanced Measurement: turn OFF "Page changes based on browser history
   events" (keep scrolls/outbound etc. optional).
3. GTM: Google tag with the Measurement ID, config parameter
   send_page_view = false, trigger Initialization - All Pages.
4. GA4 Event tag "page_view" on CE - page_view with page_location /
   page_title parameters.
5. GA4 Event tags for ecommerce: event name {{Event}} (or explicit), tick
   "Send Ecommerce data" -> Data Layer, trigger = the ecommerce regex
   trigger. Explain why one tag is fine and why separate tags are OK too.
6. Custom events click_cta / form_start / form_submit (note: GA4 Enhanced
   Measurement "form interactions" may also send form_start/form_submit ->
   disable it to avoid duplicates).
7. Testing: GTM Preview -> GA4 DebugView; Realtime; Monetization ->
   Ecommerce purchases (data delay 24–48h); internal-traffic note.


4.5 docs/meta-pixel-guide.md
----------------------------
1. Create/access a Pixel (Dataset) in Meta Events Manager; find
   META_PIXEL_ID. No ad campaign needed.
2. GTM Custom HTML tag "Meta - Base Code" with official fbq snippet using
   META_PIXEL_ID, fires fbq('init') once. Fire on Initialization - All
   Pages; DO NOT call fbq('track','PageView') inside it (SPA would only
   track the first page) — PageView is a separate tag on CE - page_view.
   Mention Community Template alternative ("Facebook Pixel" by facebookarchive
   / similar) briefly, but the guide uses Custom HTML for transparency.
3. Tag sequencing: event tags "fire after" base code (setup tag).
4. Custom JavaScript variables that convert GA4 items to Meta params:
     cjs - meta content_ids  -> items.map(i => i.item_id)
     cjs - meta contents     -> items.map(i => ({id, quantity, item_price}))
     content_type "product", content_name (single item), value, currency.
5. Event tags (Custom HTML, fbq('track', ...)):
     PageView          on CE - page_view
     ViewContent       on CE - view_item
     AddToCart         on CE - add_to_cart
     InitiateCheckout  on CE - begin_checkout
     Lead              on CE - form_submit
     Purchase          on CE - purchase  (value, currency, contents,
                                          content_ids, content_type;
                                          optional eventID = transaction_id
                                          for dedup awareness)
6. Testing: Meta Pixel Helper (Chrome extension), Events Manager -> Test
   Events, what green/yellow/red warnings mean.
7. Don't also install the Pixel via another plugin/script -> duplicates.


4.6 Duplicate events section
----------------------------
Symptoms and causes:
- 2× page_view: GA4 automatic page_view + GTM page_view tag, or Enhanced
  Measurement history events on.
- 2× PageView: PageView inside base code + separate PageView tag.
- 2× add_to_cart: Custom Event trigger AND click trigger both firing.
- 2× form_start/form_submit: Enhanced Measurement form interactions.
- 2× purchase: tag fired on Page View of /confirmation instead of
  CE - purchase; or local de-dup removed.
- Tags firing twice because GTM snippet installed twice.
How to detect: GTM Preview tag-fired counts, DebugView, Pixel Helper
counts, dataLayer inspection in console.


4.7 docs/troubleshooting.md
---------------------------
GTM not loading (ID missing/typo, env not rebuilt, ad blocker), Preview
won't connect (popup blocked, wrong URL, cookies), variables "undefined"
(DLV path / version), ecommerce data stale (missing ecommerce:null),
DebugView empty (debug_mode, preview not connected, wrong property),
Pixel Helper shows nothing (base tag not firing, ad blocker), values as
strings, purchase not visible in reports yet (processing delay).
