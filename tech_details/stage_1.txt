1. Architecture overview
------------------------

  User action (click, form submit, route change)
        |
        v
  React component / hook  --->  src/analytics/track*.ts helpers
                                        |
                                        v
                            window.dataLayer.push({ event, ecommerce })
                                        |
                                        v
                         Google Tag Manager (loaded only if GTM ID is set)
                                |                       |
                                v                       v
                         GA4 event tags          Meta Pixel tags
                     (Measurement ID in GTM)  (Pixel ID in GTM)

Key decisions:

a) No analytics code talks to GA4 or Meta directly. The site ONLY pushes to
   window.dataLayer. All IDs (GA4 Measurement ID, Meta Pixel ID) live in GTM.

b) One interaction = one dataLayer push. GA4 and Meta tags in GTM both listen
   to the same event (e.g. "add_to_cart" -> GA4 add_to_cart + Meta AddToCart).

c) Routing: a tiny custom router (~40 lines, History API: pushState +
   popstate) instead of react-router. Keeps dependencies minimal and gives us
   ONE place where every route change happens — which is exactly where the
   SPA page_view is pushed.
   Routes:
     /                 Home (hero, catalog, benefits)
     /product/:id      Product details
     /cart             Shopping cart
     /checkout         Checkout form
     /confirmation     Order confirmation

d) page_view strategy (chosen once, used everywhere):
   - The site pushes {event: "page_view", page_path, page_title, page_location}
     on initial load AND on every route change, from the router only.
   - In GTM the Google tag is configured with send_page_view = false, and GA4
     Enhanced Measurement "page changes based on browser history events" is
     turned OFF. A GA4 event tag "page_view" + Meta "PageView" fire on the
     custom event "page_view". Result: exactly one page_view per view.

e) State: React Context + useReducer for the cart (CartProvider + useCart
   hook), persisted to localStorage. No Redux.

f) GTM ID configuration: environment variable VITE_GTM_ID in a .env file
   (template in .env.example). A small inline Vite plugin in vite.config.ts
   injects the OFFICIAL GTM snippets (<head> script + <body> noscript iframe)
   into index.html at build/dev time ONLY when VITE_GTM_ID matches
   /^GTM-[A-Z0-9]+$/ and is not the placeholder GTM-XXXXXXX. Without a valid
   ID nothing is injected and the site works normally. No React component
   ever contains the ID.

g) React StrictMode stays ON. Because StrictMode runs effects twice in dev,
   analytics events are pushed from event handlers or the router where
   possible; any effect-based event (view_item_list, purchase) is protected
   by a ref / localStorage guard so it fires once.

h) Privacy: dataLayer payloads never contain name, email, phone or delivery
   address. Only product data, totals, transaction_id and the delivery
   METHOD (a non-personal option like "nova_poshta").
